## 1. Purpose and Scope

This policy defines the **group-wide rules** for data ownership, data retention, and data access control across all Coo-Cah factory digital twin deployments, the Central AI Platform, and associated operational systems (MES, EMS, ERP).

It applies to:
- All sensor time-series data ingested by the Coo-Cah DT Engine (InfluxDB edge + cloud)
- All production events and quality records generated by Siemens Opcenter MES
- All AI model training datasets derived from factory data
- All operational data shared between factory edge nodes and the Rwanda cloud hub
- All data accessed by third-party integrations (ERP, DFI reporting, auditors)

It does **not** apply to:
- Employee personal data (governed separately under NDPR/GDPR compliance policies)
- Financial / accounting records (governed by group Finance policy)
- Source code and IP assets (governed by group IP Holdings policy)

## 2. Pillar 1 — Data Ownership

### 2.1 Ownership Tiers

| Data Domain | Owner | Custodian | Notes |
|-------------|-------|-----------|-------|
| Factory sensor time-series (edge InfluxDB) | Factory OpCo (e.g., Coo-Cah Nigeria Electronics Ltd) | Digital Twin Engineering Lead | Data generated within the factory; owned by the local OpCo |
| Factory production events (MES) | Factory OpCo | MES Product Owner (factory) | Work orders, quality records, traceability data |
| Group-aggregated time-series (cloud InfluxDB) | Coo-Cah Technologies Holdings | Enterprise Data Architect | Aggregated copy; Holdings owns the group view |
| AI training datasets | Coo-Cah IP Holdings Ltd | AI Data Lead (Rwanda) | Derived datasets; owned by IP Holdings as group strategic asset |
| AI model artefacts | Coo-Cah IP Holdings Ltd | AI Engineering Lead (Rwanda) | Trained model weights and configurations |
| Group OEE / energy dashboards | Coo-Cah Technologies Holdings | Digital Twin Engineering Lead | Group visibility layer |
| DFI / investor reporting data | Coo-Cah Technologies Holdings | Chief Financial Officer | Extract provided under investor reporting obligations |

### 2.2 Ownership Decision Authority

- **Factory-level data** (edge only): Factory General Manager and Factory CTO. Changes to factory data schemas or retention rules require Factory CTO + Digital Twin Engineering Lead sign-off.
- **Group-level data** (cloud aggregation, AI training): Group CTO and Enterprise Data Architect. Changes to group data schemas, cross-factory data sharing, or AI training dataset composition require Group CTO approval.
- **IP-designated datasets** (AI model training data): Group CTO + Chief Data Officer (Rwanda). Designation of any factory dataset as an IP Holdings asset requires both approvals.

### 2.3 Data Sovereignty and Residency

| Data | Primary Residency | Backup Residency |
|------|-------------------|------------------|
| Factory edge data (hot tier) | Factory edge server (on-premises, in-country) | None (local only, 90-day rolling) |
| Cloud aggregation (warm/cold tier) | Rwanda cloud hub (Kigali) | S3-compatible object storage (Africa-region) |
| AI training datasets | Rwanda AI Platform (Kigali Innovation City) | Secondary encrypted backup (Africa-region) |

All data must remain within African jurisdictions unless explicit Group CTO + legal approval is obtained for cross-border transfer (e.g., for DFI due diligence).

## 3. Pillar 2 — Data Retention

### 3.1 Retention Tiers (Group Standard)

This table is normative and supersedes any factory-level retention rules. Factories may apply **shorter** hot-tier retention only in exceptional hardware-constrained cases with Digital Twin Engineering Lead approval; extending retention beyond group standards requires Enterprise Data Architect + Group CTO approval.

| Tier | Storage System | Retention Period | Data Scope | Deletion Rule |
|------|---------------|-----------------|-----------|---------------|
| **Hot (real-time)** | InfluxDB (edge + cloud) | 90 days | All raw sensor streams; MES events (real-time) | Auto-expire via InfluxDB retention policy; no manual deletion |
| **Warm (operational)** | PostgreSQL + object storage (S3-compatible) | 3 years | Aggregated time-series (1-min resolution); production events; quality records | Automated archival job on day 91; manual deletion requires Enterprise Data Architect approval |
| **Cold (archive)** | Object storage (S3-compatible) | 10 years | ISO 50001 audit evidence; warranty traceability records; DFI reporting extracts; AI training dataset snapshots | Automated archival job on year 3+1 day; deletion only with Group CTO + legal sign-off |
| **AI training snapshots** | Object storage (versioned) | Until superseded + 3 years | Model training datasets; feature engineering artefacts | Retain previous version for 3 years after a new version is published; never delete the version used for an active production model |

### 3.2 Legal and Regulatory Minimum Retention

The following minimum periods are driven by regulatory obligations and override the group standard if longer:

| Requirement | Regulation | Minimum Retention | Applies To |
|------------|-----------|-------------------|-----------|
| NAFDAC batch traceability records | NAFDAC Act | 5 years | Food, water, personal care, baby products factories |
| ISO 50001 energy audit records | ISO 50001:2018 | 3 years (rolling) | All factories |
| ISO 9001 quality records | ISO 9001:2015 | 3 years | All factories |
| Nigerian tax / financial records | FIRS regulations | 6 years | All Nigeria OpCos |
| Electronic signatures / records | FDA 21 CFR Part 11 | Duration of product life + 1 year | Food & pharma factories |

### 3.3 Data Deletion Controls

- No sensor or production data may be deleted within its mandatory retention period, even on factory decommission.
- Factory decommission requires a data archival plan approved by Enterprise Data Architect before any hardware is powered down.
- All deletions from cold storage must be logged in the group audit trail with approver identity and timestamp.

## 4. Pillar 3 — Data Access Control

### 4.1 Access Hierarchy

Access to Coo-Cah data assets follows a **factory-scoped by default, group-level by explicit grant** model:

| Role | Factory Data (own factory) | Factory Data (other factories) | Group Aggregated Data | AI Training Datasets |
|------|---------------------------|-------------------------------|----------------------|---------------------|
| Factory Operations Lead | Read (own factory) | ❌ No access | ❌ No access | ❌ No access |
| Factory CTO | Read + Write (own factory config) | ❌ No access | Read (own factory view) | ❌ No access |
| Digital Twin Engineering Lead | Read + Write (all factories — DT config only) | Read (DT telemetry only) | Read + Write | Read (metadata) |
| AI Data Lead (Rwanda) | Read (anonymised aggregates) | Read (anonymised aggregates) | Read | Read + Write |
| Group CTO | Full read (all) | Full read (all) | Full read + admin | Full read + admin |
| Enterprise Data Architect | Read (schema/metadata) | Read (schema/metadata) | Read + Write (schema) | Read (metadata) |
| DFI / Investor (authorised) | ❌ No direct access | ❌ No direct access | Read (reporting extracts only; time-bounded) | ❌ No access |
| External Auditor (authorised) | Read (own scope only; time-bounded) | ❌ No access | Read (scope-limited) | ❌ No access |

### 4.2 Technical Access Controls

| Interface | Mechanism | Details |
|-----------|-----------|---------|
| Factory edge → cloud DT sync | JWT (factory-scoped service account) | 24-hour token rotation; factory ID embedded in token claims |
| MES → DT edge | OAuth 2.0 client credentials | Factory-scoped client; no cross-factory read |
| AI Platform → DT cloud | JWT (read-only service account) | Read-only scope; group-level API key required for cross-factory |
| Grafana dashboards | LDAP/SSO (group Active Directory) | Role-based: factory staff see own factory; group roles see all |
| Factory manager mobile app | OAuth 2.0 + MFA | Factory-scoped; MFA mandatory for remote access |
| External / DFI reporting | Pre-generated extracts via signed S3 URLs | Time-bounded access (72 h maximum); no live API access |
| External audit access | Read-only temporary account; IAM policy | Created per audit engagement; deleted within 5 business days of audit close |

### 4.3 Cross-Factory Visibility Rules

- **Default:** A factory's data is not visible to other factories. Factory API keys are factory-scoped.
- **Group view:** Only roles with an explicit group-level API key (issued by Group CTO) can query data across factories.
- **Phase 3 autonomous operation:** Setpoint write-back from the DT Engine to OT systems requires a separate safety-reviewed DCS engineering change and cannot be granted via this policy alone.

### 4.4 Data Classification

| Class | Definition | Examples | Access |
|-------|-----------|---------|--------|
| **Operational — Public** | Non-sensitive operational metrics | Group OEE summary, energy % renewable | Freely shared internally |
| **Operational — Internal** | Factory-specific production data | Line throughput, yield by product | Factory-scoped by default |
| **Operational — Restricted** | Commercially sensitive production data | Formula / recipe data (chemicals); proprietary process parameters | Factory CTO + Group CTO only |
| **Strategic — Confidential** | AI model weights; IP-designated datasets | Trained PdM models; yield prediction models | AI Engineering Lead + Group CTO only |
| **Personal Data** | Employee records, biometric access logs | Out of scope — see NDPR/GDPR HR policy | Governed separately |

## 6. Enforcement and Compliance

- **Technical enforcement:** Access controls are enforced at the DT Engine API layer (JWT/OAuth scopes), Grafana RBAC, and object storage IAM policies. All access is logged.
- **Audit logging:** All API calls, data modifications, and access grants are logged in the group audit trail. Log retention: 10 years (cold tier).
- **Policy compliance review:** Annual review led by Enterprise Data Architect. Any factory found non-compliant will have cloud sync suspended until remediated.
- **Incident response:** Data access incidents (unauthorised access, accidental deletion, data leak) must be reported to the Group CTO within 24 hours and to the Board within 72 hours.
- **Training:** All Digital Twin Engineering, AI Data, and Factory CTO roles must complete data governance training annually.
